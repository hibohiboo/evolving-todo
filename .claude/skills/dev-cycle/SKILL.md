# dev-cycle（開発サイクルの呼び出し口）

手順の本文は `docs/process/index.md` が正。このスキルは Claude Code でその手順を回すときの段取りだけを書く。

## 0. ルートを判定する

`apps/`・`packages/` の振る舞いが変わるならフル。変わらないならライトで、このスキルは使わない。迷ったらフル。

## 1. プラン作成

- 始める前に main の CI が通っているか確かめる（セッション開始時のフックの出力。出ていなければ `node scripts/check-main-ci.mjs`）
- `docs/process/prompt-sample.md` の「1」の依頼文に沿う。質問は `grilling` スキルの手法で尽くす
- 仕様ページ（`docs/spec/`）に書いてあることは質問せず読む。未解決論点（`docs/open-questions.md`）に関わる判断だけ人間に聞く
- 質問が尽きたら `docs/plans/<日付>-<機能>.md` に8項目で書く
- 要望ファイル（`docs/backlog/`）の状態を「検討中」にし、プランのファイル名を足す

## 2〜3. プランのレビュー

別のサブエージェント（`general-purpose`）で依頼文「2」「3」を実行し、P0 を直してから次へ進む。

**ここでセッションを区切る。** プランの先頭に、済んだ手順と人間に確かめた結果を書いてから、人間に `/clear` を頼む。

## 4〜5. 実装とテスト

新しいセッションで、プランだけを読んで始める。

- 依頼文「4」。先に `AGENTS.md` のルール適用表に従って該当ルールを読む。要望ファイルの状態を「進行中」にする
- テストは `tdd` スキルで Red → Green → Refactor
- プランにない変更が必要になったら、実装せず止まって報告する

## 6. AIレビュー（並列）

`design-reviewer`・`edge-case-reviewer`・`spec-reviewer` を並列で起動し、P0〜P2 に整理する。起動するときは Agent ツールの `model` で段を指定する（`design-reviewer` は `opus`、ほかは `sonnet`）。P2 は直さず `docs/architecture/known-issues.md` に1行で記録する。P0・P1 は直して、指摘を出した観点だけで再レビューする。3ラウンドを超えたら人間に裁定を求める。

## 7. 人間レビュー

依頼文「7」で説明だけを行う。判定はしない。説明の前に、変更した画面をブラウザで操作して確かめる（`browser-check` スキル）。

## 8. push・振り返り

- `eng-practices` でセルフレビューしてから push（PR 運用なら `create-pr`）
- マージしたら、要望ファイルのサイクルの状態・PR 番号・更新日を直す（終われば状態を「完了」に）
- 振り返りは新しいセッションで、プランと PR を読んで行う。依頼文「8」で `docs/process/evolution.md` の候補への追記案を出す。採用は人間が決める
