# 開発体制の進化ログ

開発プロセス自体の変更を「候補 → 評価 → 採用／却下」の型で記録する。運用は[開発プロセス](index.md#体制の進化)が正。却下も削除せず理由付きで残す。

記録するのは「ルール・依頼文・スキル・サブエージェント・CI など、進め方に関する変更」であり、機能の設計判断はプランドキュメント（`docs/plans/`）に書く。

このページには、まだ評価していない候補と書き方だけを置く。評価を終えた候補と、採用・却下の記録は、月ごとのページ（`evolution/<年-月>.md`）に書く。[体制の進化のタイムライン](timeline.md)は月ごとのページから年表を組み立てる。

## 候補（未評価）

サイクルの途中で気づいた人（人間・AIどちらでも）が追記する。書式：`- [ ] <候補> — <気づいた状況・根拠>（<日付>）`。評価したら、この行を `- [x]` にして、評価した月のページの「候補（評価済み）」へ移す。

- [ ] 画面が増えたら、依存の向きを Biome の `noRestrictedImports` で止める — 移植元（CarTaGraphFantasy）は層ごとの import の禁止を `biome.json` に書いている。いまは画面が1つで層も2つなので、ルールの文書（アーキテクチャルール「依存の向き」）だけにした。画面が増えて違反が1回起きたら入れる。止め方の案：機械（lint）（2026-10-14）
- [ ] 画面のコード（`pages`・`shared`）が `@evolving-todo/schemas` を import するのを、Biome の `noRestrictedImports` で止める — 2026-10-15、API ドキュメントを入れたときに、アーキテクチャルール「依存の向き」に文書で書いた。移植元は lint で止めている。違反が1回起きたら入れる。止め方の案：機械（lint）（2026-10-15）
- [ ] 仕様書サイトの左メニューに載っていないページを、`pnpm docs:build` で止める — 移植元でも、いまは設定のコメントで「ページを足したらメニューにも足す」と書いているだけ（移植元の進化ログの候補）。止め方の案：機械（ビルド時の検査）（2026-10-14）

## 書き方

採用・却下は、その月のページ（`evolution/<年-月>.md`。無ければ作る）の「採用済み」「却下」の先頭に足す（新しいものを上に）。書式：`### <日付> <タイトル>` の下に、内容・理由・反映先と、次の2つを書く。却下は理由を必ず書く。

- **きっかけ** — 誰が・何で気づいたか：人間レビュー／AI レビュー／作業中の失敗／人間の要望／計画（基盤整備などのプラン）
- **止め方** — 同じことをどう防ぐか：機械（CI・git フック・lint・Claude Code のフック・ビルド時の検査や自動生成）／レビュー観点／手順・ルール（文書に書く）／置き場所（ページ・ファイルを新設・移動する）。複数あれば並べる

きっかけ・止め方は、まとめの1行（`- **きっかけ** — … ／ **止め方** — …`）か、小項目ごとの1行（`- きっかけ：… ／ 止め方：…`）で書く。読めないとビルドが止まる（`scripts/evolution-timeline.mjs`）。止め方は最初の「。」（括弧の外）までを読むので、まだやっていない案は「。」の後ろに書く。
